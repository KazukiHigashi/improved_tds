# PLSによる低自由度ツール制御の設計

作成日: 2026-08-17
基盤: TDS論文（3rd draft）の TDS-based scissors control（式6〜8）
対象: spray variant 1〜5（Shadow Hand Lite, 13アクチュエータ自由度）
関連資料: `synergy_analysis_plan.md`, `real_robot_integration.md`

## 1. 論文手法との差分

論文の制御則は次の3式である。

```
x̂ = x̄ + S_TDS ρ            (6)   姿勢 = 平均姿勢 + シナジー × スコア
c  = f(ρ)                   (7)   ρ を掃引してツール状態を実測し同定
x̂ = x̄ + S_TDS f⁻¹(c_target) (8)   目標ツール状態から姿勢を決める
```

はさみタスクではこれで完結する。**手が柄に通った状態から始まるため、
どの ρ に対しても手はツールを保持しており、落とすという事象が存在しない**。

スプレーは異なる。ボトルは手に固定されておらず、把持は学習中に獲得される
接触状態である。同じ掃引で手が開けば、ツール角は手の姿勢の関数ではなくなる。
ここから2つの変更が導かれる。

### 1.1 軌道を2段階にする

初期姿勢DBの姿勢は**意図的に対象物と非接触**に作られている（接触は学習で
獲得させる方針）。したがって初期姿勢から直接 ρ を掃引すると、何も掴んでいない
姿勢から始まってしまう。

```
第1段階（把持）: 初期姿勢 x_init → 基準姿勢 x̄_pose
第2段階（操作）: x̄_pose → x̄_pose + w·ρ
第3段階（保持）: x̄_pose + w·ρ を維持
```

第1段階は論文には存在しない工程である。

### 1.2 基準姿勢を初期姿勢ごとに取る

論文の `x̄` は全成功姿勢の平均である。spray では初期姿勢が32種あり、
**姿勢間の差は操作による姿勢変化よりはるかに大きい**ため、全体平均は
どの姿勢からも到達しない、かつ何も把持していない姿勢になる。

そこで基準姿勢を初期姿勢 p ごとに取る。

```
x̄_p = 方策がツールを保持していた区間の平均姿勢（初期姿勢 p のエピソード平均）
x(ρ) = x̄_p + w·ρ
```

### 1.3 シナジーをPCAではなくPLSで求める

`synergy_analysis_plan.md` の解析により、**PCAの第1主成分がツール自由度と
対応しない**ことが判明している（spray4 で相関 +0.01、spray1 で +0.33）。
はさみタスクでは第1主成分の寄与率が45〜68%で支配的だったが、
spray では成立しない。

PLS第1軸は単一軸でツール状態と r = 0.70〜0.93 の相関を持ち、5分割交差検証でも
同じ値を維持する。したがって `S_TDS` を PLS第1軸 `w` に置き換える。

PLS第1軸は目的変数が1次元のとき閉形式で、**各関節とツール状態の共分散ベクトル
そのもの**である（sklearn の出力と機械精度で一致することを確認済み）。

```
w = Xᵀy / ‖Xᵀy‖      X: 姿勢ごとに中心化した関節行列, y: ツール状態
```

符号は「ρ が増えるとツール状態が増える」向きに固定する。PLSは符号を決めない
ため、これを怠るとツールごとに指令の符号が反転する。

### 1.4 PLSとPCAの関係

**PLSはPCAと別の空間を作るのではなく、主成分をツール関連度で重み付けし直したもの
である。** 主成分基底 `v_i` で PLS第1軸を展開すると、係数は各主成分スコアと
ツール状態の共分散に一致する。

```
w · v_i = v_iᵀXᵀy = (X v_i)ᵀ y = s_iᵀ y  ∝  cov(第i主成分スコア, ツール状態)
```

5変種すべてで、係数ベクトルと正規化共分散ベクトルの内積が 1.000000000000
（機械精度）であることを確認した。

#### 上位k主成分でどれだけ表現できるか

PLS第1軸を上位k主成分へ射影したときの残存率 ‖proj‖²（1.0で完全表現）。

| variant | k=1 | **k=2** | k=3 | k=4 | PLS1とPC1の角度 | PLS1と上位2次元の角度 |
|---|---|---|---|---|---|---|
| spray1 | 0.202 | **0.978** | 0.996 | 0.998 | 63.3° | 8.5° |
| spray2 | 0.952 | **0.955** | 0.997 | 1.000 | 12.7° | 12.3° |
| spray3 | 0.912 | **0.982** | 0.996 | 0.999 | 17.3° | 7.8° |
| spray4 | **0.000** | **0.854** | 0.878 | 0.979 | **88.8°** | 22.4° |
| spray5 | 0.751 | **0.982** | 0.999 | 1.000 | 29.9° | 7.8° |

**上位2主成分で 85〜98% を表現できる**（角度で 7.8〜22.4°）。
一方 **第1主成分だけでは足りない**。spray4 では PLS1 と PC1 がほぼ直交する（88.8°）。

したがって「ツール自由度は第1・第2主成分の線形結合として表れる」という
当初の見立ては正しい。ただし**係数は寄与率順ではない**。

#### 部分空間としては一致しない

2成分PLS部分空間と上位2主成分部分空間の主角度 [deg]。

| variant | 主角度 |
|---|---|
| spray1 | 31.2, 0.4 |
| spray3 | 33.8, 0.5 |
| spray5 | 30.8, 0.8 |
| spray2 | 76.8, 0.1 |
| spray4 | 83.7, 4.4 |

**第2主角度がほぼ0°** なので両部分空間は共通の1次元方向を持つが、
第1主角度が 31〜84° あり部分空間としては一致しない。PLSの2成分目は
デフレーション後の残差から取るため、分散最大化とは別の方向を選ぶ。

離れが大きい spray2（PC1の寄与率83%と突出）と spray4（PC1がツールと無相関）は、
いずれも極端な変種である。

#### 主成分の役割は固定ではない

「第1主成分が把持、第2主成分が操作」という役割分担があるか、各主成分スコアと
ツール状態・把持力の相関で調べた。

| variant | | 寄与率 | ツール状態 | 把持力 |
|---|---|---|---|---|
| spray4 | PC1 | 48.7% | **+0.011** | **−0.559** |
| | PC2 | 21.0% | **+0.724** | +0.267 |
| spray1 | PC1 | 54.9% | +0.332 | +0.361 |
| | PC2 | 33.9% | **+0.829** | **+0.739** |
| spray3 | PC1 | 52.5% | **+0.817** | −0.527 |
| | PC2 | 19.3% | +0.373 | −0.148 |
| spray5 | PC1 | 41.3% | **+0.771** | +0.408 |
| | PC2 | 27.3% | −0.525 | +0.441 |
| spray2 | PC1 | 83.0% | **+0.665** | +0.042 |
| | PC2 | 9.6% | −0.108 | −0.123 |

**役割分担が成立するのは spray4 だけである。** PC1 がツールと無相関（+0.011）で
把持力と相関（−0.559）、PC2 がその逆になっている。操作軸と把持力軸が 79.0° と
ほぼ直交する変種である。

spray1 では PC2 が両方を担う（+0.829 と +0.739）。軸間角度 5.9° で、
トリガーを引くことと握り込むことが同じ運動だからである。
spray3・spray5 では逆に PC1 が操作を担う。spray2 の PC2 はどちらとも無相関で、
**何も担っていない主成分**も存在する。

したがって「PC1 が把持、PC2 が操作」という一般則はない。PLS1 が PC2 に多く
含まれることだけからは、PC1 が何をしているかは決まらない。

#### K（S_TDSの列数）と制御自由度は別物である

上の表現率は「PCAで k 次元に truncate したとき操作方向が残るか」を測る量であり、
**タスク実施に必要な自由度ではない**。

問うている方向によって答えが変わる点に注意が要る。上位k主成分での表現率:

| variant | 方向 | k=2 | k=4 | k=6 |
|---|---|---|---|---|
| spray1 | PLS1（共分散最適） | 0.978 | 0.998 | 0.999 |
| spray1 | 最小二乗（相関最適） | **0.062** | 0.138 | 0.232 |
| spray4 | PLS1 | 0.854 | 0.979 | 0.995 |
| spray4 | 最小二乗 | **0.042** | 0.080 | 0.148 |

**相関最適な方向は上位6主成分に入れても 15〜30% しか残らない。** PLS1 が k=2 で
残るのは PLS が分散の大きい方向を選ぶからで、「上位2主成分で足りる」は
PLS1 という特定の方向についての性質である。

そのうえで、k=2 が答えているのは**論文の `S_TDS` に何列必要か**である。

```
S_TDS = [p₁, ..., p_K] ∈ R^(D×K)      論文の定義（K = ツールの内在自由度）
```

はさみは K=1 で足りたが、spray では **K=1 で操作方向が失われる**
（spray4 は表現率 0.000）。**K=2 が要る。**

一方、指令する自由度は 1 のままである。2次元部分空間の中の1本の直線上を
動かすだけだからである。

```
ρ ∈ R¹  →  x = x̄_p + (S_TDS u) ρ       u は2次元部分空間内の単位ベクトル
```

FF制御の実測（§3.2、`tds_control.py`）では ρ という数値1つで追従誤差
中央値 0.89〜2.24度を達成しており、把持は基準姿勢が構成上保つため追加の
指令次元は要らなかった。

| 量 | 問い | spray の値 |
|---|---|---|
| K（S_TDS の列数） | PCAで何次元残せば操作方向を含むか | **2** |
| 制御自由度 | 実際にいくつ数値を指令するか | **1** |

**論文が「K = ツールの内在自由度」と定義している点は spray では成り立たない。**
ツール自由度は1つだが、PCA基底で操作方向を保持するには2次元要る。記法上の
問題であり、TDSの主張（1自由度で操作できる）自体は保たれる。
論文では **`S_TDS` の列数と制御入力の次元を分けて書く**必要がある。

#### 論文への含意

PCAとPLSは対立する手法ではない、と書ける。PLSは主成分の共分散重み付き和であり、
**寄与率順に上位を取る操作を、ツール関連度順に取り直す操作に置き換えたもの**
と位置づけられる。

## 2. 把持の扱い

### 2.1 直交方向は基準姿勢に留まる

`x(ρ) = x̄_p + w·ρ` という形により、**w に直交する12方向はすべて把持済みの
基準姿勢の値のまま**である。したがって w 自身が手を開かない限り、
把持は構成上保たれる。

これは論文の式(6)をそのまま使うことの副産物だが、はさみでは意味を持たず、
把持が必要なツールで初めて効いてくる性質である。

### 2.2 把持力軸との角度が変種依存である

把持力を独立に制御できるかは、**操作軸 w と把持力軸 w_grasp の角度**で決まる。
w_grasp は同じ手順で、目的変数を把持接触の法線力合計として求めた PLS第1軸である。

| variant | 角度(w, w_grasp) | 操作スコアと把持力の相関 | 独立制御 |
|---|---|---|---|
| spray1 | **5.9°** | +0.833 | 不可 |
| spray3 | 17.5° | −0.545 | 困難 |
| spray2 | 46.5° | +0.053 | 部分的 |
| spray5 | 71.2° | +0.186 | 可能 |
| spray4 | 79.0° | −0.185 | 可能 |

**spray1 ではトリガーを引くことと握り込むことが同じ関節運動である**（5.9°）。
この場合、把持力は操作の従属変数であり、独立には動かせない。

### 2.3 把持力軸への直交化は操作範囲を犠牲にする

「操作軸から把持力成分を除去すれば把持を一定に保てる」という設計を検証した。

```
w_⊥ = w − (w·w_grasp) w_grasp     （正規化）
```

結果は §3 の表のとおりで、角度の小さい変種では**ツール可動範囲が
1/7〜1/4 に落ちる**。spray3 では 0.106 → 0.015 rad となり、実用にならない。

したがって「把持軸をフィードバック制御し操作軸のみを指令する」構成は
**全変種に適用できる方針ではない**。角度に応じて方式を選ぶ必要がある。

| 角度 | 方針 |
|---|---|
| 60°以上 | 操作軸を指令し、把持軸を力フィードバックで独立に保持 |
| 30〜60° | 直交化した操作軸を使い、失った範囲を把持軸側の指令で補う |
| 30°未満 | 直交化しない。把持力は操作の従属変数とし、**上限クランプで安全確保** |

## 3. 評価結果

### 3.1 手順

初期姿勢6種 × ρ を12点掃引 × 軸2種 × 5変種 = 720回のロールアウト。
各回は把持60step → 操作60step → 保持80step。ボトル設置位置は固定。
実装は `improved_tds/experiments/evaluate_tds_control.py`。

### 3.2 結果

`span` はツール状態の可動範囲（rad, 姿勢6種の中央値）、`monotone` は
ρ とツール状態の相関の絶対値（f が単調に同定できるかの指標）。

| variant | 軸 | span中央値 | span最小 | span最大 | 把持維持 | monotone |
|---|---|---|---|---|---|---|
| spray1 | PLS | **0.157** | 0.136 | 0.165 | 72/72 | 0.995 |
| spray1 | 直交化 | 0.042 | 0.036 | 0.063 | 72/72 | 0.989 |
| spray2 | PLS | **0.151** | 0.104 | 0.167 | 72/72 | 0.959 |
| spray2 | 直交化 | 0.041 | 0.031 | 0.051 | 72/72 | **0.320** |
| spray3 | PLS | **0.106** | 0.088 | 0.131 | 72/72 | 0.960 |
| spray3 | 直交化 | 0.015 | 0.007 | 0.028 | 72/72 | 0.982 |
| spray4 | PLS | 0.091 | 0.059 | 0.104 | 72/72 | 0.992 |
| spray4 | 直交化 | 0.070 | 0.044 | 0.087 | 72/72 | 0.995 |
| spray5 | PLS | 0.119 | 0.096 | 0.150 | 72/72 | 0.995 |
| spray5 | **直交化** | **0.133** | 0.080 | 0.153 | 72/72 | 0.992 |

### 3.3 読み取り

**把持は全720回で維持された。** 落下・転倒はゼロ。§2.1 の構成が意図どおり
機能している。把持を別途制御しなくても、基準姿勢を把持状態に取るだけで足りる。

**f(ρ) は単調に同定できる。** PLS軸では相関 0.959〜0.995 で、論文がはさみで
用いたランプ関数フィッティングがそのまま適用できる形である。
唯一の例外は spray2 の直交化軸（0.320）で、この条件では f が同定できない。

**直交化の可否は §2.2 の角度で予測できる。**

- spray5（71.2°）: 直交化しても範囲が落ちない（0.119 → 0.133、むしろ増加）
- spray4（79.0°）: 0.091 → 0.070 と小幅な低下
- spray1（5.9°）、spray3（17.5°）: 0.157 → 0.042、0.106 → 0.015 と壊滅的

角度が予測指標として機能している。

**可動範囲はトリガー可動域の17〜35%にとどまる。** トリガー上限0.4 radに対し
span は 0.07〜0.14 rad である。論文でも同様の現象が報告されており
（学習時の最大57.3度に対し実現35〜45度）、原因も同じと考えられる。すなわち
**方策は目標到達までに複雑な姿勢軌道を辿るのに対し、同定時は基準姿勢からの
線形補間で姿勢を変えている**ためである。

ただしこれは軸 `w` の限界ではなく、**ρ の掃引範囲の取り方の限界**である。
§3.4 で範囲を広げると可動域は 44〜56% まで拡大する。

### 3.4 ρ の掃引範囲

#### 現状の取り方（論文の式9と同じ）

```python
scores = samples.q[pose] @ w
grid = np.linspace(scores.min(), scores.max(), 12)
```

方策が実際に訪れた保持姿勢のスコアの最小〜最大。論文の
`ρ_input = g(ρ_min, ρ_max, 12)` に対応する。

**これが §3.3 の可動範囲を決めていた。** 方策は目標角へ至るまでに複雑な姿勢
軌道を辿るのに対し、同定時は基準姿勢からの線形補間で姿勢を変えるため、
同じ ρ で到達するツール角が小さくなる。結果として観測スコア範囲が
「必要な範囲」より狭く見積もられていた。

#### 拡張時の取り方

2方式を検証した。

```python
# 方式A: 観測範囲のスケール倍（関節ごとのクリップは許容する）
grid = np.linspace(scores.min() * k, scores.max() * k, n)

# 方式B: 運動学的限界（どの関節も飽和しない範囲）
#   ref を指令範囲へ丸めた上で、各関節 j について
#     a_j = (high_j - ref_j) / w_j,  b_j = (low_j - ref_j) / w_j
#     ρ ∈ [min(a_j, b_j), max(a_j, b_j)]
#   の全関節での共通部分
```

**方式Aを採用する。方式Bは保守的すぎて使えない。** 基準姿勢 `x̄_p` は実測関節角
であり、接触力で押さえ込まれて指令範囲を越えている関節が存在する。そのため
spray1・姿勢0での方式Bの範囲は ρ ∈ [0.000, +1.008] となり、**負方向がゼロ**で
1ステップも動かせない。方式Aでは一部の関節が飽和しても残りが動き続けるため、
軸方向が徐々に変化しながら可動域を稼げる。

#### 拡張の効果

初期姿勢3種 × ρ 25点 × 5変種。ツール可動範囲 [rad]、掃引を観測範囲の
k倍に制限したときの値。

| variant | ×1（論文） | ×2 | ×3 | ×4 | 拡大率 |
|---|---|---|---|---|---|
| spray1 | 0.132 | **0.179** | 0.179 | 0.179 | ×1.36 |
| spray2 | 0.139 | **0.174** | 0.174 | 0.174 | ×1.25 |
| spray3 | 0.081 | 0.199 | 0.215 | **0.222** | **×2.74** |
| spray4 | 0.067 | 0.133 | 0.175 | **0.225** | **×3.36** |
| spray5 | 0.105 | 0.170 | 0.199 | **0.212** | ×2.02 |

トリガー可動域0.4 radに対する被覆率は **17〜35% → 44〜56%**。
**×4でも全180回のスイープで把持が維持され、落下・転倒はゼロ。**
拡大が最大なのは元の被覆率が最低だった spray4（17%→56%）と spray3（20%→56%）。

#### 拡張の代償と打ち切り基準

| variant | 単調性 ×1 | 単調性 ×4 | 可動域が飽和する ρ | 推奨 |
|---|---|---|---|---|
| spray1 | 0.995 | **0.880** | 0.54 | ×2 |
| spray2 | 0.959 | **0.820** | 0.63 | ×2 |
| spray3 | 0.960 | 0.952 | 0.53 | ×4 |
| spray4 | 0.992 | 0.938 | 0.73 | ×4以上 |
| spray5 | 0.995 | 0.927 | 1.21 | ×3 |

**単調性（ρ とツール角の相関）が低下する。** 関節が順に飽和して実効的な軸方向が
変わるためで、ランプ関数フィッティングの精度が落ちる。spray1・spray2 は
×2で可動域が頭打ちになり、それ以上は単調性だけが悪化する。

したがって固定倍率ではなく、**掃引しながら可動域の増分が閾値を下回った時点で
打ち切る**手順を採る。変種ごとに最適倍率が ×2〜×4以上と異なる。

### 3.5 基準姿勢の取り方

§1.2 では基準姿勢 `x̄_p` を「保持区間の実測関節角の平均」としたが、
取り方は他にもある。4通りを比べた。

| 名前 | 取り方 |
|---|---|
| `measured` | 保持区間の実測関節角の平均（§1.2 の定義） |
| `measured_clipped` | 上を指令範囲へ丸めたもの |

#### 基準姿勢の影響は ρ 範囲より大きい

同じ spray2 でも、取り方しだいで 0.058 rad から 0.372 rad まで6倍以上の開きが
出る。ρ の範囲を広げて得られた効果はせいぜい3倍だったから、
**どこまで動かすかより、どこから動かし始めるかの方が効いている**。

#### 実測の方がよく動く理由

はじめは「実測の関節角は接触に押し戻された値だから、そのまま指令したのでは
押しが足りなくなる」と考えていた。結果は逆で、実測の姿勢の方がよく動く。

理由は指令の飽和である。学習した方策は指令値を可動端に張り付けて力を出しており、
飽和の割合はおよそ29%だった。その指令値をそのまま基準姿勢にすると、出発点で
すでに端まで来ているため、そこから軸の向きに動かそうとしても動けない。
spray1 では実際、前にも後ろにも余地がなかった（§3.4 方式Bの範囲が [0, 0]）。

実測の関節角は、接触に押し戻された分だけ端の内側に入っている。
だから動かす余地が残る。

`measured` と `measured_clipped` の差は最大 0.002 rad で、
**指令範囲を外れた関節を丸めても可動域は変わらない**。

#### spray2 だけの例外

spray2 は `commanded_min_tool` が最良で、トリガー可動域の93%を動かせた。
他の変種では同じやり方が最下位に近いので、spray2 固有の事情と見るべきである。

spray2 は人差し指のPIP関節ひとつがほぼ全体を担っており（荷重0.87）、
初期姿勢が変わっても同じ動きが出る変種だった（姿勢別軸の角度が中央値9.4°）。
浅い側に基準を置けば、そこから先に大きな余地が残るのだと思われる。

#### 選び方

基準姿勢の良し悪しは「軸の向きにどれだけ動く余地が残っているか」で決まっていた。
この余地は §3.4 方式Bの計算で、シミュレーションを回さずに求まる。
実際の可動域ともよく対応している。spray1 では、余地 1.008 の姿勢が可動域 0.179、
余地ゼロの姿勢が 0.071 だった。

したがって候補となる姿勢をいくつか作って余地を計算し、いちばん大きいものを
選ぶ、という決め方が使える。

ただし基準姿勢はツールを握っていなければ意味がない。余地を大きく取ることと
握りを保つことは、場合によっては両立しないはずである。今回は握りが崩れなかった
ため確かめられていない。

gym の TimeLimit と環境自身のカウンタの両方を延長する必要がある

実機では整定に時間がかかるため論文どおり 5 s が妥当だが、
**シミュレーションの評価では 1.2 s で同じ結果が得られる**。掃引を
1.2 s 基準に戻せば実行時間は約 1/4 になる。

### 3.7 基準姿勢のバイアスで把持力は変えられるか

基準姿勢を把持力軸に沿ってずらし、握りの強さを変えられるかを調べた。
σ はフィードバックではなく固定バイアスである。

```
x(ρ, σ) = x̄_p + w·ρ + w_grasp⊥·σ
```

## 4. 制御則のまとめ

```
事前（シミュレーション）
  1. 学習済み方策から均等ロールアウトを収集（初期姿勢×目標角グリッド、設置位置固定）
  2. 保持区間の平均姿勢を1エピソード1サンプルとして抽出、初期姿勢ごとに中心化
  3. w      = PLS第1軸（目的変数 = ツール状態）、ρ増加でツール状態増加の向きに符号固定
     w_grasp = PLS第1軸（目的変数 = 把持法線力）
  4. 角度∠(w, w_grasp) から §2.3 の方針を選択
  5. x̄_p = 初期姿勢 p の保持区間平均姿勢

実行時
  第1段階  x_init → x̄_p            （把持の確立）
  第2段階  x(ρ) = x̄_p + w·ρ        （ρ を掃引して f を同定、以降は f⁻¹ で指令）
           ρ の範囲は観測スコア範囲のスケール倍とし（§3.4 方式A）、
           可動域の増分が閾値を下回るまで倍率を上げて打ち切る
  安全拘束 関節可動域クランプ、トルク上限クランプ、
           ∠が小さい変種では把持力の上限クランプ
```

実機への指令変換（結合関節J2→J1の複製、13次元の並び、制御周期）は
`real_robot_integration.md` に従う。

## 5. 把持の扱いの決定と、今後の案

### 5.1 決定: 把持はTDS制御の対象外とする

TDS-based tool control は簡易制御の枠組みであり、把持の確立と維持はその対象外とする。
現在のスプレー環境と同様に、**対象物は床に置いたまま操作する**前提で進める。

実測でもこの判断は裏付けられている。基準姿勢を把持力軸に沿ってずらせば握りは
強められるが（§3.7）、最大でも 3.8 N で、方策が握っていた 20〜110 N には届かない。
位置指令で基準姿勢を与える方式そのものの限界である。

### 5.2 未検証の案: トルク入力 + 把持シナジーのフィードバック制御

**行動空間を位置指令からトルク入力に変え、把持を担う関節連動にフィードバックを
かければ、把持を含めた制御が成立する可能性がある。**

現在うまくいかない理由は、位置サーボに測定済みの関節角を指令しているためである。
接触が押し返す分だけ関節は目標に届かず、力は指令から決まらない。トルク入力なら
把持力を直接指令でき、接触力フィードバックで閉じれば、対象物のばらつきに対しても
握りを保てるはずである。

構成としては次を想定する。

```
操作軸  w        : ツール自由度に対応する関節連動。位置または速度で指令
把持シナジー w_g : 把持を担う関節連動。トルク指令とし、接触力でフィードバック
```

本資料の評価はすべて位置指令で行っており、この案は未検証である。
論文で今後の展望として言及する候補。

## 6. 未解決の論点

1. **可動範囲は拡張後も44〜56%にとどまる。** ρ の掃引範囲を広げることで
   17〜35%から改善したが（§3.4）、トリガー可動域の半分強である。
   残りの制約要因は未特定で、基準姿勢 `x̄_p` の位置（実測関節角が指令範囲外に
   ある関節を含む）と、線形補間による姿勢遷移の両方が候補である。
   論文が提案する「TDS制御則を強化学習の拘束として組み込む」案のほか、
   基準姿勢を指令可能な姿勢へ取り直す案が考えられる。
2. **拡張すると ρ とツール角の単調性が落ちる。** 関節の飽和が原因で、
   spray1・spray2 では ×4 で 0.88・0.82 まで低下する。ランプ関数以外の
   フィッティング形、または飽和領域を除外する打ち切り基準が要る。
3. **変種横断の共通シナジーがない。** PLS軸同士の角度は中央値76°で、
   ツールごとに同定し直す必要がある。少数サンプル適応の対象は
   f(ρ) だけでなく w も含まれることになる。
4. **把持力の絶対値が大きい。** 保持区間の法線力合計は変種により
   20〜110 N で、実機のシャドウハンドにそのまま適用できる値ではない。
   実機展開前に力のスケーリングが要る。
5. **実機検証は未実施。** 本資料の結果はすべてシミュレーションである。
