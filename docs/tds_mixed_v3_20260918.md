# 全15タスク PCA/PLS TDS評価（2026-09-18）

## 対象と再現性

Push 1–5、Spray 1–5、Scissors 1–2は `tool_control_v2_20260917`、Scissors 3–5は `scissors_control_v3_20260918` の成果を使用する。
角度範囲の網羅を優先し、全タスクとも `best_pose_coverage_policy.zip` を採用する。これは最大平均成功率の `best_success_policy.zip` と異なる場合がある。
初期姿勢はそれぞれの学習で使用した32件。ソース・モデル・姿勢群を新実験フォルダに複製し、入力モデルと姿勢群のSHA256をmanifestに記録する。既存の学習結果と旧TDS評価を上書きしない。

## 成功姿勢の再収集と分割

- 同じ32初期姿勢×101目標値（範囲内を0.01刻みで正規化）を全タスクで評価し、各3,232エピソードの記録を作る。各エピソードの失敗も監査用に残す。
- RLモデルの観測・制御仕様は学習時と一致させる。Scissors 3–5の再収集だけはv3の速度制限を含む。
- 成功保持窓はScissors 10Step、Push/Spray 5Step。最初に保持が成立した窓の最後の**実測関節姿勢**を保存する。平均姿勢は用いない。指令姿勢も速度制限後に実際に適用されたものを保存する。
- 32初期姿勢を16 Fit / 8 Calibration / 8 Testに分割。seedは20260911–20260915の5通りで固定し、結果を見て分割を選び直さない。
- 各Fitには、目標・実測工具状態が同じ10分割区間に属する成功姿勢を各区間10件、合計100件使用。操作13関節のRMS差0.01 rad未満を重複として除外する。
- Fitに使うXと対応する工具状態・元行番号を `fit_databases/<task>/fit_seed<seed>.npz` に別途保存する。PCA/PLSは同じ100件を使用する。
- 数値範囲の端から許容誤差分はみ出した姿勢はFitから除く。全域10区間の網羅性と、厳密な端点への到達は区別する。
- 5分割すべての件数・角度区間・Calibration参照姿勢の充足を検査する。不足時はそのタスクを未完了として記録し、水増し・成功基準緩和・分割の選び直しは行わない。他タスクは継続する。

## PCA/PLSとFF制御

以前のstrict/adaptive評価コードを継続使用する。操作軸はFit姿勢の初期姿勢内中心化から算出し、工具状態との符号を揃える。
Scissorsは操作1自由度、Push/Sprayは把持後に操作する2自由度。strict段階では把持軸なし、残差PCA、把持指標PLSを比較し、adaptive段階では従来と同じ把持指標PLSの枝を使用する。
既存の内部名 `force_pls` / `grasp_force` は、環境に法線力の値がない場合には接触割合・接触数を代理指標として使う。特にPushの値をニュートン単位の把持力と解釈しない。代理指標が変化せずPLSを推定できない場合も、無断の代替軸を使わず失敗として記録する。

FF評価では全Scissorsに同じ研究用把持判定と直接絶対指令を使用し、3–5だけにRL用速度制限を残さない。
各試行は独立reset→把持100Step→操作ramp50Step→保持50Step。把持喪失による終了を無視して操作を続けない。

前回同様に `legacy / direction / range / joint` の4条件を比較する。
JointではCalibrationだけを使って把持・preload・物理スコア区間・向きを選択し、等張回帰した平均工具応答の逆写像で目標角度をFF操作する。
Testデータを軸推定・区間選択・逆写像の学習に用いない。

## 評価・可視化

- 主指標：RL目標範囲に対する把持維持下のCoverage。
- 併記：把持維持率、全域9目標への独立実行によるMAE・正規化MAE、Calibration到達可能範囲内のMAE、スコアと工具状態の相関。
- Coverageは観測最小最大の区間幅であり、すべての中間角度が到達可能という証明ではない。
- Calibration不成立も保存し、全条件集計のCoverage・把持維持率には0として含める。MAEの条件付き集計と実行件数を明示する。
- 各タスク×5分割=75レポート。PCA/PLSの両方を評価する。
- 代表seed20260911では、13スコアの姿勢画像にタスク・方式・スコア・工具状態の字幕を付ける。
- Joint方式が成立した場合、事前指定したTest先頭姿勢・範囲中央目標について20Stepごとの画像を追加する（途中終了時は最終画像も保存）。成立しなかったJoint制御の画像を成功例として作らない。
- HTMLのグラフにはFitに使った成功姿勢100件の散布図、Calibration応答、Test操作応答を重ねる。

## 実行

`scripts/run_tds_20260918.py` をFDMS仮想環境のPythonから起動する。
4ワーカーで最初に15タスクの再収集・Fit監査、その後に評価を実行する。評価は1ワーカー1環境であり、RLの4環境VecEnv学習ではない。
出力：`analysis/tds_mixed_v3_20260918`。`status.json`と`index.html`に段階・失敗を記録。全75レポート完了後、`summary/index.html`を自動生成する。
未完了タスクがある場合、全15タスクが完了した比較表を作ったようには扱わない。
独立した非表示プロセスで動かし、エージェントによる常時監視はしない。
